# 阶段 1：核心查询与示例终端程序

## Goal

交付可构建的 C++23 核心库与终端程序，使用明确标记的虚构邮件完成列表、账号筛选和详情查看。本阶段不接入真实邮箱、持久化、AI 或回复功能。

## Architecture

`mail_assistant` 负责参数校验、显示和退出码，`mailai_core` 负责账号筛选、排序与邮件查找。查询接收内存数据并返回拥有字符串的结果，显示逻辑不修改输入。

使用 CMake、Ninja 和 CTest，只依赖 C++ 标准库。核心库与所有目标启用标准 C++23，关闭编译器扩展。整体方向见[设计规格](../../specs/mail-ai-assistant-design.md)第 2、3、9 节。

## Spec

- S-1：列表支持全部账号和指定账号筛选，按接收时间降序、同时间邮件 ID 升序排列，并保留邮件所属账号及其显示名。
- S-2：已知账号没有邮件时返回成功的空结果，未知账号返回带账号上下文的错误。空账号集合与空邮件集合也应返回空结果；发现邮件引用不存在的账号时，返回带账号及邮件上下文的错误。
- S-3：详情按稳定邮件 ID 查询，不能把列表行号当作 ID。ID 使用无符号 64 位整数，0 无效；查无邮件与无效 ID 分别报告。
- S-4：邮件时间使用有符号 64 位 UTC 时间戳，返回值拥有字符串和容器。输入数据保持不变，中文主题与正文完整保留。
- S-5：终端提供帮助、列表、账号筛选和详情功能。无参数显示帮助，账号 `all` 表示不筛选，成功展示邮件时标明“数据来源：示例”。
- S-6：参数必须完整校验后才能调用查询。缺失、重复、多余或未知参数，以及非完整十进制正整数或溢出的邮件 ID，均作为参数错误。
- S-7：正常结果写 stdout，错误写 stderr。成功与空列表退出 0，查询或运行失败退出 1，参数错误退出 2；失败时 stdout 为空。

## 验收条件

- AC-1：从干净目录构建核心库、终端程序和测试，构建无警告；测试在 Debug 和 Release 下均实际执行条件检查。
- AC-2：使用乱序输入和相同接收时间的邮件验证排序，账号筛选后的结果与来源账号准确，空结果与未知账号可区分。
- AC-3：用有效、缺失、零值及无符号整数边界 ID 验证详情查询，中文及错误上下文完整，查询不改变输入数据。
- AC-4：通过终端测试验证帮助、列表、筛选、详情、示例标记和退出码；缺失或非法参数不会触发查询。
- AC-5：实际运行终端程序完成列表、筛选与详情查看，非法 ID 返回参数错误；Debug 和 Release 的全部阶段测试通过。

## Tasks

### Task 1：可构建的核心查询

目标：提供独立于终端显示的邮件列表和详情查询能力。

步骤：

1. 定义账号、邮件、查询结果和带上下文的错误类型，明确 ID、时间戳及数据所有权。
2. 编写列表查询测试，覆盖全部账号、指定账号、空结果、未知账号和排序规则。
3. 编写详情查询测试，覆盖稳定 ID、无效 ID、未找到邮件和整数边界。
4. 实现账号检查、邮件筛选及按既定规则排序的列表查询。
5. 实现按稳定 ID 查找详情的查询，保留来源账号和中文内容。
6. 建立核心库及 CTest 入口，确保测试在 Release 下仍检查结果。
7. 运行核心查询测试，核对排序、筛选、所有权与错误上下文。

验收：AC-1、AC-2、AC-3；核心库可独立构建，全部核心查询场景符合 Spec。

### Task 2：CLI 列表、详情与错误反馈

目标：将核心查询接入可实际运行的示例终端程序。

依赖：Task 1。

步骤：

1. 编写终端测试，覆盖帮助、邮件列表、账号筛选、详情和两路输出。
2. 补充参数错误测试，覆盖缺值、重复选项、未知选项、非法 ID 和溢出输入。
3. 实现命令解析，完整校验参数后再调用核心查询。
4. 实现列表与详情显示，保留稳定 ID、来源账号、中文内容和示例来源标记。
5. 建立程序入口，以虚构账号和邮件装配查询数据。
6. 接入实际程序的冒烟测试，检查退出码和可辨认的邮件内容。
7. 分别在 Debug 和 Release 下构建并运行全部阶段测试。
8. 实际运行帮助、列表、筛选、详情和非法参数场景，核对结果及退出码。
9. 更新 README 中的构建与使用说明，并审查参数边界和阶段范围。

验收：AC-4、AC-5；真实程序行为与终端测试一致，原核心查询测试继续通过。
