# 阶段 2：收取单个邮箱的邮件，保存后离线查看

## Goal

连接一个真实的学校邮箱，把收件箱中的邮件解析并保存到 SQLite。用户断网后仍能查看邮件，重复同步不会产生重复记录，程序中途退出后还能继续处理未完成的邮件。

本阶段只处理一个账号的 INBOX。AI、SMTP、回复、多账号管理、watch 和 JSON 输出留到后续阶段。

## Architecture

CLI 负责接收命令和显示结果，业务服务负责组织操作，邮件和存储模块完成具体工作。同步时，先从服务器取得邮件编号，把需要处理的邮件记入数据库，再逐封下载、解析和保存。处理失败的邮件继续留在数据库的任务记录中，供下次重试。

查看列表和详情时，只读取本地数据库。示例模式使用阶段 1 的虚构邮件，单独提供数据。创建这些服务时不打开数据库，也不连接网络，等用户执行对应命令后再访问资源。

SQLite 模块负责创建和打开数据库、保存账号设置、查询和写入邮件，以及记录同步进度。libcurl 负责 IMAP 通信，GMime 负责解析 MIME 和转换字符编码，libxml2 负责从 HTML 中提取正文。资源通过 RAII 管理，业务函数通过 `std::expected` 返回结果或错误，由 CLI 显示。

使用 macOS 本机的 C++23、CMake、Ninja 和 CTest。依赖最低版本为 SQLite 3.37、libcurl 8.0、GMime 3.2、libxml2 2.9。Python 和 OpenSSL 命令行工具用于本地 TLS 测试服务器。构建方法见 [README](../../../../README.md)，实际验证过的版本见[依赖记录](../../../dependencies.md)。

本阶段承接[阶段 1](../phase-01-foundation/plan.md)，具体要求依据[整体设计](../../specs/mail-ai-assistant-design.md)第 3、7、8、9 节。数据库结构、打开规则和错误映射见[SQLite 生命周期设计](../../specs/mail-ai-assistant-sqlite-lifecycle-design.md)。

## Spec

- **S-1：读取配置。** 数据目录先使用显式设置的路径，再尝试绝对路径的 XDG 目录，最后使用 HOME 目录。同步必填项缺失或为空时报错。端口必须能完整解析为 1–65535 的十进制整数，implicit TLS 默认使用 993，STARTTLS 默认使用 143，两种方式都校验证书和主机名。配置只保存密码所在的环境变量名，连接时才读取密码值。

- **S-2：打开数据库和保存账号。** 只支持版本 1。只有读写模式可以把空的版本 0 数据库初始化为版本 1，只读模式不能初始化。版本 0 但已有内容、版本不受支持、结构不符或数据库损坏时，报错并保留原数据。已有账号可以修改显示名，但不能更换服务器、端口或用户名。

- **S-3：查看邮件。** 列表按接收时间从新到旧排列，时间相同时按本地 ID 从小到大排列，并返回账号名称、解析状态和历史标记。账号存在但没有邮件时返回空列表，账号不存在时报错。详情按稳定的本地 ID 查询，附件保持原顺序。查询支持只读连接，返回的字符串和容器在数据库关闭后仍然有效。

- **S-4：检查 ID 和存储值。** 查询详情时，ID 为 0 返回 `invalid_argument`，超过 SQLite 有符号整数范围或查无记录时返回 `mail_not_found`。数据库中的本地 ID 必须为正数，服务器 UIDVALIDITY 和 UID 必须是非零的 32 位无符号整数。时间戳保留完整的 64 位有符号整数值。发现字段类型、数值范围或解析状态非法时，返回 `storage_error`，不截断数值，也不返回已经读出的一部分结果。

- **S-5：读取同步状态。** 每个账号和文件夹分别保存状态。账号存在但没有同步记录时返回空状态，账号不存在时报错，账号或文件夹为空时返回参数错误。时间戳的 NULL、0 和负数含义不同，读取时分别保留。SQL 参数按完整字符串长度绑定，包括内嵌 NUL。状态和待重试邮件查询的错误阶段分别为 `storage.state`、`storage.pending`，错误包含输入账号，邮件 ID 保持为空。

- **S-6：读取仍需重试的邮件。** 只查指定账号、文件夹和当前 UIDVALIDITY 下允许重试的任务，按 UID 从小到大返回。没有同步记录、没有当前 UIDVALIDITY，或没有符合条件的任务时，成功返回空列表。之前失败的邮件不能因为后来发现了更大的 UID 就被漏掉。查询不修改任务、进度或错误记录。

- **S-7：一起保存相关记录。** 新发现的邮件任务和“已经发现到哪个 UID”的进度，必须在同一个事务中保存。用账号、文件夹、UIDVALIDITY 和 UID 判断是否为同一封远端邮件，重试时保留原本的本地 ID，不能通过替换整行重新分配 ID。邮件和附件也必须一起保存，只有解析和保存都成功后才移除对应任务。输入无效或事务失败时，原有记录保持不变。

- **S-8：保留失败邮件。** 解析成功后清空解析错误，没有主题时使用 `(无主题)`。解析失败时保留原始字节、非空错误原因和重试任务，以 `(解析失败)` 为主题、空字符串为正文保存一条邮件记录。临时下载失败的邮件下次继续重试。确认服务器上已经没有该邮件后，停止重试，保留已有本地历史。

- **S-9：处理新邮件和 UIDVALIDITY 变化。** UIDVALIDITY 改变后，旧 UID 不能再用于定位新邮件。必须在同一个事务中把旧邮件标记为历史，并使旧任务失效。首次同步最多安排 UID 最大的 20 封邮件，之后只下载新邮件和仍需重试的邮件。从服务器取得的 UID 列表先去重并排序。本轮没有任何失败时，才更新最后成功时间。

- **S-10：控制事务和写锁。** SQLite 写事务只包住必要的数据库操作，不在网络请求期间保持写事务。原文按字节保存，查询使用参数绑定。写命令必须取得数据目录的独占锁，默认最多等待 5 秒。只读缓存不获取这把锁。

- **S-11：解析正文和附件。** 支持 UTF-8、GB18030、Base64、quoted-printable 和常见 multipart 邮件。优先使用纯文本正文，没有纯文本时再从 HTML 提取文字，忽略 script/style，也不请求外部资源。附件只保存名称、媒体类型和解码后的大小。遇到不支持的字符集时明确报错。

- **S-12：限制邮件大小和复杂度。** 原文最多 20 MiB，MIME 最多嵌套 32 层，最多包含 256 个部件。解析超限返回 `parse_error`。附件大小在绑定前检查是否超过 SQLite 整数范围。下载过程中原文超过大小限制时，立即停止并返回可重试错误。

- **S-13：只读收取邮件。** 用服务器的 UID 和 UIDVALIDITY 定位邮件，通过 `BODY.PEEK[]` 下载，保持服务器已读状态不变。接收时间取服务器 INTERNALDATE。协议元数据和邮件原文分别解析。重新连接后再次核对 UIDVALIDITY，再决定是否继续使用之前的远端标识。

- **S-14：处理网络错误。** 默认连接超时为 10 秒，总超时为 30 秒。临时连接失败最多重试 2 次，分别等待 1、2 秒。认证、证书、参数和解析错误直接报告。错误说明所属账号、出错步骤和原因，不包含密码或真实邮件正文。

- **S-15：区分缓存和示例。** 默认从本地缓存读取列表和详情，不要求密码或网络。缓存不存在时列表为空，不能自动换成示例邮件。只有命令开头显式指定 `--demo` 才使用阶段 1 的示例，示例模式不能执行同步。帮助命令和参数错误不能触发数据库访问或网络请求。

- **S-16：显示结果。** 终端显示稳定 ID、数据来源、附件信息、解析状态和历史状态。可能影响终端显示的控制字符需要转义，正文保留正常换行，数据库中的原值不变。正常结果写 stdout，诊断写 stderr。全部成功退出 0，全部失败或无法执行退出 1，参数错误退出 2，部分成功退出 3。空邮箱或没有新邮件也算成功。

## 验收条件

- **AC-1：** 配置测试覆盖目录选择、必填值、TLS 模式、端口范围和非法输入，共享类型及原有内存查询测试通过。记录实际依赖版本，并在本机检查 libcurl 是否支持 IMAP、IMAPS 和 TLS。
- **AC-2：** 用临时 SQLite 数据库验证初始化、关闭后重新打开和只读访问。不支持的结构、版本和账号连接设置变更会被拒绝，已有记录保留。初始化或提交失败不会留下部分修改，故障解除后可以重试成功。
- **AC-3：** 数据库测试验证列表筛选与排序、完整详情、附件顺序、同步状态和仍需重试的邮件。空结果、未知账号、整数范围、非法字段都返回规定结果。带引号或内嵌 NUL 的字符串按完整值匹配，查询失败后连接仍可继续使用。
- **AC-4：** 重复保存同一封邮件时，本地 ID 不变。邮件与附件、新任务与发现进度分别做到一起成功或一起失败。测试还需验证解析失败重试、远端邮件消失和 UIDVALIDITY 变化。写锁冲突时在规定时间内报错，锁释放后可以成功取得。
- **AC-5：** 虚构 MIME 样本能得到预期的中文正文和附件信息，正文选择、编码转换及未知字符集处理符合要求。三项资源限制都有边界测试，一封坏邮件不会阻止处理其他邮件。
- **AC-6：** 实际用 libcurl 连接本地 TLS IMAP 测试服务器，验证正常下载、空邮箱、认证、证书、超时、有限重试、邮件消失、UIDVALIDITY 变化和 INTERNALDATE。未读邮件下载后仍未读，错误信息不泄露密码。
- **AC-7：** 同步测试使用真实 SQLite 和 MIME 解析，验证首次收取范围、重复同步、较小 UID 失败后的重试、中断后继续和 UIDVALIDITY 变化。成功保存的邮件不重复下载，数据库整体不可用时停止同步。
- **AC-8：** CLI 测试验证离线查看、没有缓存、示例模式、参数错误、状态显示和退出码。能区分合法的最大无符号 ID 和溢出输入。帮助和查看命令都不会触发收信。
- **AC-9：** 显式启用真实邮箱验证，完成收取、查看、重启、重复同步，以及移除密码后的离线查看。邮件可读，ID 不变，没有重复记录，服务器已读状态不变。真实邮箱探针只在 `MAILAI_LIVE_TESTS=1` 时运行，不注册到默认 CTest。凭据或服务器不可用时，真实邮箱部分仍未通过验收。
- **AC-10：** Debug 和独立 Release 构建均无警告，配置、查询、存储、MIME、IMAP、同步、CLI、运行时服务和实际程序入口的全部已注册测试通过。默认测试不连接真实邮箱。阶段审阅中影响验收的问题均已修正并验证。

## Tasks

### Task 1：读取配置，准备共享类型和依赖库

目标：提供经过检查的配置、各模块需要的数据类型，以及可构建的依赖库。

步骤：

1. 编写配置测试，覆盖数据目录选择、缺失或空值、TLS 模式、端口范围和非法输入。
2. 实现数据目录选择，按规定顺序尝试各个来源，找不到有效目录时返回错误。
3. 实现同步配置读取，检查必填项和端口，只保存密码所在的环境变量名。
4. 用 `std::expected` 统一返回业务结果，补齐解析后的邮件、附件、同步状态和错误信息所需的类型。
5. 修改内存邮件列表的返回结果，保留解析状态和历史标记。
6. 接入四个运行时依赖库，检查本机版本以及 libcurl 支持的协议。
7. 运行配置测试和原有查询、CLI 测试，记录实际验证过的依赖版本。

验收：AC-1。配置和共享类型可供后续任务使用，MIME 解析和真实收信分别在对应任务中验证。

### Task 2：把邮件和未完成的同步任务保存在 SQLite 中

目标：把邮件和还没处理完的任务保存在数据库里，让用户能够离线查看，并在程序重启后继续同步。

依赖：Task 1。

步骤：

1. 用临时 SQLite 数据库编写存储测试，检查打开、查询和保存数据的结果，以及操作失败后能否重试。
2. 按数据库设计实现打开规则。只初始化空的版本 0 数据库，对版本 1 检查结构，其他情况报错并保留数据。
3. 实现账号设置保存。允许修改显示名，拒绝更换已有账号的服务器、端口或用户名。
4. 实现本地邮件列表查询，带上账号显示名。邮件按接收时间从新到旧排列，时间相同时按本地 ID 从小到大排列。
5. 实现邮件详情查询，在同一个读事务中读取一封邮件和它的附件，按原顺序返回附件。
6. 实现 `state`，用一条 SQL 读取指定账号和文件夹的同步状态。账号不存在时报错，账号存在但没有同步记录时返回空状态。
7. 实现 `pending`，查出指定账号和文件夹中仍需重试的邮件，只保留当前 UIDVALIDITY 对应的任务，并按 UID 从小到大返回。之前处理失败的邮件也要查出来，不能因为后来发现了更大的 UID 就漏掉它们。用一条 SQL 完成查询，函数内部不要另开事务。
8. 补充查询测试，检查整数边界和非法存储值，并确认查询失败后同一个连接仍能继续使用。
9. 实现 `schedule`，把新发现且需要下载的邮件记入任务表，同时记录已经发现到哪个 UID。这两项修改放在同一个事务中保存。首次只安排规定数量的邮件，同一份 UID 列表重复处理时不新增重复任务。
10. 处理 UIDVALIDITY 变化，在同一个事务中把旧邮件标记为历史，并使旧 UIDVALIDITY 下的任务失效。
11. 实现邮件和附件保存，让它们在同一个事务中一起写入。重复保存同一封远端邮件时，保留已有的本地 ID。
12. 处理解析失败的邮件，保存原文和错误原因，并保留重试任务。只有解析和保存都成功后，才移除该任务。
13. 保存下载失败的原因和每轮同步结果。临时失败的邮件下次继续重试，确认已从服务器消失的邮件停止重试。
14. 为写命令实现数据目录独占锁，检查锁被占用时能否按时超时，以及释放后能否重新取得。
15. 运行全部存储测试，检查关闭后重新打开是否保留数据、只读查询是否改变数据，以及事务失败是否留下部分修改。

验收：AC-2、AC-3、AC-4。分别检查数据库打开、查询、写入和失败处理是否符合要求。

### Task 3：解析中文邮件正文和附件信息

目标：从邮件原文中读出中文正文和附件信息，无法解析时说明原因。

依赖：Task 1。

步骤：

1. 准备虚构邮件样本，覆盖中文字符集、传输编码、multipart、附件和缺失主题。
2. 用 GMime 解析邮件头、传输编码和字符集，将文本转换为有效的 UTF-8。
3. 实现正文选择，优先取纯文本，没有纯文本时用 libxml2 从 HTML 提取文字。
4. 按原顺序提取附件名称、媒体类型和大小，大小使用解码后的字节数。
5. 实现原文大小、嵌套层数和部件数量限制，遇到超限或未知字符集时返回明确错误。
6. 运行样本和边界测试，逐项核对正文、附件信息和错误结果。

验收：AC-5。解析结果与样本的预期正文、附件和错误一致。

### Task 4：通过 IMAP 下载邮件，保持已读状态不变

目标：按服务器标识下载对应邮件，不把未读邮件改成已读。

依赖：Task 1。

步骤：

1. 建立本地 TLS IMAP 测试服务器，在临时目录生成测试证书。
2. 用 libcurl 实现连接、认证和证书校验，分别设置服务器地址、用户名和密码。
3. 读取 INBOX 的 UIDVALIDITY 和 UID 列表，作为本次同步使用的邮箱信息。
4. 按远端标识下载邮件原文和 INTERNALDATE，使用 `BODY.PEEK[]` 获取正文。
5. 实现超时和有限次数的重试。重新连接后先核对 UIDVALIDITY，再决定是否继续使用之前的远端标识。
6. 限制下载大小，按错误原因返回对应类型，并确保错误内容不包含密码。
7. 运行网络测试，覆盖正常下载、空邮箱、认证、证书、超时、断连和服务器上的邮件变化。
8. 对比下载前后的邮件标记，确认未读邮件仍然未读。

验收：AC-6。通过实际 TLS IMAP 请求检查收到的邮件内容、错误结果和服务器标记。

### Task 5：完成增量同步，并在失败或重启后继续

目标：串起发现邮件、下载、解析和保存的流程，让未完成的邮件下次还能继续处理。

依赖：Task 2、Task 3、Task 4。

步骤：

1. 编写同步测试，用可以控制返回结果的邮件源，配合真实 SQLite 存储和 MIME 解析检查同步结果。
2. 将取得的 UID 列表去重并排序，为首次选中的邮件或之后新发现的 UID 登记任务，同时记下已经发现到哪个 UID。
3. 读出仍需重试的任务，逐封下载、解析，再调用存储模块保存处理结果。
4. 实现单封邮件失败后的处理，让其他邮件继续执行，临时下载失败和解析失败的邮件留到下次重试。
5. 处理邮件从服务器消失和 UIDVALIDITY 改变的情况，保留本地历史，停止重试已经失效的任务。
6. 保存本轮成功和失败数量、每封失败邮件的原因，以及最后尝试和最后成功时间。
7. 在数据库整体不可用时终止本轮同步，不再推进发现进度。
8. 测试重复同步、程序重启，以及较小 UID 失败而较大 UID 成功的情况，确认成功邮件不重复下载，失败邮件不会漏掉。

验收：AC-7。分别检查刚发现邮件就中断、部分邮件成功后重启，以及 UIDVALIDITY 变化后的数据库记录。

### Task 6：让 CLI 默认查看真实缓存
