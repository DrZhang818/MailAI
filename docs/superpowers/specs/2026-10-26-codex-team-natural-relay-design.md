# Codex Team 自然接力设计

## 目标

`team` 不再把每条用户输入改写成任务协商提示。用户输入应原样进入一个正常的 Codex 回合；GPT 与 DeepSeek 都清楚自己在同一个共享对话中，并能通过自然的发言接力共同讨论、执行或把话筒交还用户。

## 交互

默认顺序：

```text
用户 → GPT → DeepSeek → GPT → 用户
```

这不是轮数上限。模型可以在回复末尾使用隐藏标记继续接力：

```text
[[next:gpt]]
[[next:deepseek]]
[[next:user]]
[[end]]
```

标记只控制发言权，不进入公开正文，不规定任务内容、角色、阶段或执行人。

没有标记时使用默认顺序；GPT、DeepSeek 各发言足够完成一次自然交换后交还用户。模型通过标记可以继续任意多轮。

## 上下文

- 每个模型保留自己的 Codex 线程。
- 新用户消息第一次发送时保持原文。
- 另一位模型发言后，以带发言者标签的未读对话片段送入当前模型。
- 模型只在会话开始收到一次最小房间说明：自己的名字、组员名字、用户在场、隐藏交接标记。之后不再注入任务阶段或分工模板。

## 工具与写入

- 默认允许普通 Codex workspace-write 和现有审批流程。
- `--read-only` 仍可强制全部回合只读。
- 同一时刻只有一个模型活跃，因此工具调用和文件写入天然串行。
- 命令事件默认不在终端显示；`/verbose` 切换显示。发言、文件修改摘要和错误仍显示。

## 安全

- 用户可随时 `/stop`。
- 相同模型、相同正文、相同下一棒的接力模式重复出现时，判定为空转并交还用户。
- 单个模型回合继续使用现有超时和审批拒绝策略。
- 不自动提交、重置或清理用户已有修改。
