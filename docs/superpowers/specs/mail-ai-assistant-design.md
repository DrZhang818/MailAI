# 个人终端邮件 AI 助手：设计规格

日期：2026-10-19。流程：Superpowers brainstorming，架构级设计。

状态：用户已回复“通过”，本书面规格已批准。阶段 1 的核心查询与示例 CLI 已验收；真实邮件依赖集成、邮箱连接和模型调用尚未验证。

项目协作约定：新文件按主题命名，不加日期前缀；当前专注本项目，暂停维护原实习计划和 CCG 学习记录。

## 1. 目标与范围

用 C++23 开发个人使用的本地终端工具，同时连接 QQ 与学校邮箱，自动整理邮件、汇报重要内容与待办，并辅助回复。普通回复生成可编辑草稿；一键回复对明确选中的邮件直接生成并发送。

已确认的选择：独立子命令、可选前台 `watch`、云端模型 API、`report` 默认更新后汇报，以及模块化 CLI＋核心库＋SQLite。测试、测试辅助与验证由导师维护；从阶段 2 起用户也参与测试编写。业务实现由导师在终端给出完整参考和必要解释，用户理解后抄入源码。导师检查实际代码并验证，不把参考代码的提供记为用户已独立实现。

首个完整版本包含多账号、中文邮件解析、三种汇报、隐藏与恢复、用户规则、草稿发送、一键批量回复和状态恢复。按第 9 节逐阶段实现，以验收推进。

后续按需要增加图形／网页前端、Gmail／Outlook OAuth、本地模型、附件正文理解、回复全部和自然语言自由查询。首版附件展示名称、类型与大小。

## 2. 结构与职责

一个可执行程序 `mail_assistant` 调用一个核心库 `mailai_core`。每次命令在本进程执行；SQLite 保存跨命令状态。`watch` 在前台周期运行。

| 模块 | 职责与依赖 |
|---|---|
| CLI | 解析参数、展示文本／JSON、设置退出码；调用业务入口 |
| 同步服务 | 按账号增量收信、保存进度与失败项；调用邮件接入与存储 |
| 分析与汇报服务 | 请求分析、应用用户规则、筛选排序；调用 AI 客户端与存储 |
| 回复服务 | 收集会话、生成草稿、创建发送任务、推进状态；调用邮件接入、AI 与存储 |
| 邮件接入 | IMAP 获取、SMTP 提交、MIME 解析与序列化；管理协议句柄 |
| AI 客户端 | 云端 HTTPS 请求、超时、响应字段与类型校验；返回分析或回复正文 |
| 本地存储 | SQLite 查询、短事务、缓存、草稿与发送状态恢复 |

依赖方向：CLI → 业务服务 → 邮件／AI／存储。业务入口返回数据或带上下文的错误，CLI 负责显示。未来前端通过适配层调用相同入口。

先用普通函数和具体类型，随功能增加文件。工程使用 CMake、CTest 和 WSL Ubuntu；构建与运行通过 `wsl.exe -d Ubuntu -- ...` 调用 WSL 工具。

语言标准采用 C++23；核心库公开 `cxx_std_23` 编译要求。所有项目目标设置 `CXX_STANDARD 23`、`CXX_STANDARD_REQUIRED ON`、`CXX_EXTENSIONS OFF`。CMake 最低版本为 3.20，标准设置依据 [CMake 官方文档](https://cmake.org/cmake/help/latest/prop_tgt/CXX_STANDARD.html)。

网络候选为 [libcurl](https://curl.se/libcurl/c/imap-fetch.html)，JSON 候选为 [nlohmann/json](https://json.nlohmann.me/integration/cmake/)。MIME 候选为 [mailio](https://github.com/karastojko/mailio)，在中文、HTML、multipart 与字符集样本通过后固定选型和版本。SQLite 保存本地数据。候选依赖尚未完成集成验证。

## 3. 数据、账号与同步

| 记录 | 核心内容 |
|---|---|
| Account | 稳定 ID、显示名、邮箱地址、收发连接参数、认证方式、凭据引用、启用状态 |
| Mail | 本地稳定 ID、来源账号、文件夹、服务器标识、地址、主题、接收时间、正文、线程字段、解析状态 |
| Analysis | 摘要、类别、重要性与理由、待办及原文依据、回复状态、上下文签名、模型／提示词版本 |
| Draft | 原邮件集合、来源账号、收件人、主题与正文、用户意图、版本 |
| SendOperation | 操作／批次 ID、去重键、冻结内容、状态、错误、关联草稿或原邮件集合 |

持久记录拥有自己的字符串和容器。句柄通过 RAII 管理；临时借用数据的生命周期限制在调用期间。凭据值放在本地环境变量或不入库、不纳入 Git 的凭据文件，数据库只保存引用。日志与模型输入排除凭据。

邮件 ID 按用户选择采用 `std::uint64_t`，0 保留为无效 ID；CLI 按无符号整数完整解析，负数、0 与溢出输入作为参数错误。UTC epoch 秒数建议保留 `std::int64_t`，以表达纪元之前的时刻。

数据表逐步建立为 `accounts`、`sync_state`、`messages`、`analyses`、`user_overrides`、`drafts`、`send_operations`。停用账号保留已有邮件供查看；移除账号仅解除本地接入，历史记录保留为停用账号数据。

同步规则：

- 收件箱增量同步，已发送文件夹用于补充会话；文件夹不可用或上下文截断时明确标注上下文有限。
- 首次每账号收件箱最近 20 封，历史与已发送正文按会话需要获取；连接验证可先取 5 封。后台获取保持服务器已读状态。
- 服务器定位唯一键为 `account_id＋folder＋UIDVALIDITY＋UID`；本地稳定 ID 用于命令。UIDVALIDITY 改变后启用新的服务器标识范围，已有本地记录保留为历史，并显示重新索引状态。
- 会话按同账号内的 Message-ID、In-Reply-To、References 关联；主题相同仅作线索，信息不足时保留为独立会话。同一邮件在多个文件夹的记录可关联，但不同账号分别保存。
- 成功记录与同步进度在短事务中提交，失败项单独保留重试机会；较大的成功 UID 不得覆盖较小失败项。
- 中文主题、纯文本、HTML 正文提取、常见 multipart、Base64、quoted-printable 与首批样本涉及的字符集转换必须验证；解析失败保留索引和明确原因。

默认 `watch` 每轮结束后等待 120 秒，再开始下一轮同步与分析；频率与首次范围可配置。普通查看读取本地数据，`report` 按第 4 节更新。

## 4. 分析、汇报与用户规则

`report` 执行：同步 → 保存 → 分析新增／失效内容 → 保存分析 → 应用用户规则 → 筛选排序 → 展示。有效缓存复用；仅切换排序不重新分析正文。

模型输出采用校验后的结构化字段：中文摘要 1–3 句；类别为学校／课程、招聘／实习、个人沟通、订阅推广、其他；重要性为紧急、重要、普通、低价值，附理由；待办允许为空，截止时间允许为空并保留原文；回复状态为待我回复、等对方回复、已处理、仅供知悉、暂不确定。

重要性与待回复独立判断，结合可用会话和已发送记录。时间不明确时保留原始表达或空值。分析缓存签名覆盖正文、会话及已发送上下文、模型服务／模型配置、提示词版本；相关内容改变时失效。个人规则独立保存，在查询时覆盖 AI 判断。

| 汇报模式 | 行为 |
|---|---|
| time | 按接收时间从新到旧；可选升序 |
| important | 紧急、重要、普通分组，同组从新到旧；低价值按隐藏规则处理 |
| reply | 展示待我回复的会话，附未解决问题与判断依据 |

默认全部启用账号、近 24 小时；每条包含账号、稳定邮件 ID、时间、发件人、主题和摘要。时间内部存 UTC，展示采用本地时区。

自动隐藏条件为低价值、无需回复、无待办；保留原文、隐藏原因、数量和恢复入口。用户明确关注／忽略发件人、修改类别或重要性、恢复邮件的规则优先。解析或分析失败项在汇报中另列为待处理，保留查看入口。

云端模型服务地址、模型名与凭据可配置，允许每账号暂停 AI。首个 AI 客户端只承诺一种经实测的 HTTP／JSON 协议，接入阶段记录其供应商与协议；配置地址不等于兼容任意服务商。模型仅接收任务所需邮件与上下文，正文始终作为待分析数据。

## 5. 回复与发送

普通回复：会话上下文 → 生成并保存草稿 → 展示账号、收件人、正文与草稿 ID → 用户编辑 → `send` 发送保存版本。

一键回复：固定本次稳定 ID 集合及可选统一意图 → 按会话归并并保存待办操作 → 生成内容 → 保存冻结内容 → 自动发送 → 逐项结果。该命令直接执行生成与发送，无逐封审核或额外发送确认；未指定集合时报参数错误，范围固定为本次选择。`watch` 仅同步与分析。

同账号同会话的多封选中邮件合并为一项回复，并展示合并关系；使用可用的最新上下文。AI 的待回复判断供参考，用户明确选中的邮件仍进入处理流程。

回复使用原邮件所属账号的固定身份，默认单人回复。收件人由应用按合法 Reply-To／From 或用户明确编辑的地址确定，线程头由应用生成。AI 只返回正文。默认沿用会话语言，语气简洁礼貌，支持署名、风格和本次意图。

缺少事实或个人决定时，默认基于已知事实生成收悉／澄清回复；无法形成有效回复时跳过并说明原因，也可配置缺信息时全部跳过。提示词限定事实来源，语义质量通过标注样本评估；应用校验响应结构、正文非空与未替换占位符。生成失败或无效内容记为失败，跳过有独立状态。实际发送文本持久保存。

### 发送状态与重复操作

操作状态：`queued → generating → ready → sending → submitted`；普通草稿发送从 `ready` 开始。异常终态为 `failed`、`unknown`、`skipped`、`cancelled`。草稿独立保存，普通回复生成草稿时尚未创建发送操作。

- 手动发送以草稿 ID＋版本去重。一键发送按账号、同会话内排序后的选中 ID 集合及规范化意图去重；数据库唯一约束保证同一初始键只有一项操作，重复命令返回已有结果。重试及显式新回复使用关联的新键，保留原操作。
- 生成完成后持久保存冻结的账号、收件人、线程头与正文，再通过条件更新领取待发任务。网络调用置于数据库事务之外。任务保存失败时停止该项发送。
- 服务器明确接受才记为 `submitted`；它表示已提交，最终送达仍可能受退信影响。提交后保存已发送副本失败单独记录，仅重试存档。
- 确定未提交的错误记为 `failed`；提交结果不确定或重启发现遗留 `sending` 时记为 `unknown`。未知项保留冻结内容与操作 ID，等待核对或用户显式重试。
- `operations retry` 为失败项创建关联重试，沿用冻结内容；生成阶段失败则重做生成。重试键包含被重试的操作 ID，同一 retry 命令重复执行返回同一关联重试；再次重试针对新的失败操作 ID。原操作的重复命令仍返回原记录。未知项的重试要求显式 `--retry-unknown`，并保留原未知状态和新操作关联。
- 明确发起新回复用 `--new` 创建新的操作范围；仍在发送中或结果未知的相同目标先返回已有状态。对未知操作使用上述专用重试入口。
- 批处理单项失败后继续其余项；中断取消尚未开始发送的项，已在提交中的项先记录明确结果或未知。任务恢复仅自动推进确定未提交的项。

去重保证针对应用中的同一操作，SMTP 不确定结果保留未知状态；不承诺跨网络的端到端恰好一次投递。

## 6. CLI 约定

| 命令 | 用途 |
|---|---|
| `accounts list / add / edit / enable / pause / remove / test` | 管理账号，分别检测收信与发信连接 |
| `sync --account all` | 同步入库 |
| `analyze --pending` | 分析待处理或失效记录 |
| `inbox [--account school] [--hidden]`、`show 42` | 查看本地邮件／详情，`--hidden` 查看已隐藏项 |
| `report --mode time\|important\|reply [--since 24h] [--account all]` | 自动更新后汇报；`--offline` 仅使用本地结果 |
| `reply 42 [--intent "询问其他时间"]` | 生成草稿 |
| `draft show 7 / edit 7 / discard 7`、`send 7` | 管理草稿及发送保存版本 |
| `reply --ids 42,43 --send-now [--intent "确认收到"] [--new]` | 指定集合直接生成并发送 |
| `operations list / show OP_ID / retry OP_ID / cancel OP_ID` | 查询、重试或取消；未知重试另加 `--retry-unknown` |
| `ignore 42`、`restore 42` | 隐藏／恢复邮件 |
| `rules list / set / remove` | 设置关注／忽略发件人、类别及重要性覆盖；规则关联稳定 ID |
| `watch --interval 120` | 前台轮询，同步与分析 |

示例 ID 为虚构数据。`draft edit` 使用配置的终端编辑器，保存成功才增加版本。正文编辑与信封地址编辑使用不同字段，发送采用当前保存版本。

正常结果写 stdout，进度和诊断写 stderr；列表及结果命令提供 `--json`。退出码：0 全部成功；1 全部失败或命令无法执行；2 参数错误；3 部分失败、未知或跳过。空收件箱／无新邮件正常返回 0。

同一数据目录只允许一个 `watch`。修改业务状态的命令持有独占进程锁，`watch` 每轮持锁、等待期间释放；其他写命令等待到配置上限后报忙，读取本地状态的命令可继续运行。SQLite 写事务保持短小，操作状态条件更新仍保留。

## 7. 错误与恢复

错误包含账号或操作 ID、阶段、类型与可读原因。区分认证、连接、解析、模型请求、响应校验、存储和发送结果未知。

每次网络操作配置连接超时与总超时。连接／服务临时故障可有限退避重试，默认最多重试 2 次；认证、参数、结构校验错误直接报告。SMTP 重试另受第 5 节提交状态约束。

单账号超时后继续其他账号。`report` 在同步或 AI 失败时展示已有本地结果，并列出账号更新时间、分析失效／失败及未处理项。保存失败仅影响当前项，存储整体不可用时终止命令并返回错误。

重启恢复账号、邮件、分析、个人规则、草稿和操作状态。重复命令复用已有记录；恢复不会自动重投已提交或未知操作。

## 8. 验收与证据

| 场景 | 通过条件 |
|---|---|
| 工程起步 | 从干净构建目录构建，核心库与 CLI 链接，虚构 inbox 展示稳定 ID、账号、主题 |
| 中文与编码 | 固定纯文本、HTML、multipart、编码和字符集样本正确解析；不支持项明确报告 |
| 增量与恢复 | 重复同步无同定位键重复记录，失败项可继续，重启后已有数据可查；UIDVALIDITY 变化可定位 |
| 双账号隔离 | QQ 与学校邮箱均可收发，单账号失败不阻断另一账号；回复身份和目标正确 |
| 汇报与覆盖 | 三种模式符合固定样本；切换模式复用缓存，内容变化失效；用户规则保留，隐藏可恢复，失败可见 |
| 回复质量 | 标注样本记录会话状态与回复误判；缺事实遵循默认策略，引用依据可核对 |
| 草稿流程 | 普通 reply 仅生成草稿；编辑并 send 后，提交内容与保存版本一致 |
| 一键范围 | 对选中测试邮件一条命令生成发送；同会话归并可见，未选邮件保持未处理 |
| 操作恢复 | 重复命令及模拟崩溃不自动重投同一操作；不确定提交转未知；存档失败不重投正文 |
| 部分失败 | 单项失败后其他项继续，账号／操作可定位，退出码与 JSON 结果一致 |

固定样本、模拟模型响应与可控网络结果用于日常测试，覆盖规则和错误路径；真实邮箱、真实 AI 与测试发信单独集成验证，使用本人可控制的收发地址。AI 质量以标注样本和错误记录评估。

## 9. 阶段与交付

| 阶段 | 任务 | 阶段验收 |
|---|---|---|
| 1 工程起步 | CMake、核心库／CLI、Account／Mail／错误类型、虚构 inbox | 构建并运行展示 |
| 2 单邮箱收取与保存 | 认证、IMAP、MIME、SQLite、同步进度与去重 | 真实邮件可读，重复同步与重启正确 |
| 3 AI 分析与汇报 | 一家云端模型、结构校验、缓存、三种汇报、隐藏／覆盖 | 固定样本和失败可见性通过，report 自动更新 |
| 4 多邮箱与轮询 | QQ＋学校账号管理、统一列表、watch、失败隔离 | 两账号稳定运行，单侧失败另一侧继续 |
| 5 草稿与发送 | 会话、生成／编辑、SMTP、身份、去重、未知恢复 | 草稿待 send，正确身份提交，同一操作复用 |
| 6 一键批量回复 | 明确集合、意图、归并、直接发送、部分失败与取消 | 一条命令完成指定范围，恢复规则通过 |
| 7 终端交付 | help／JSON／退出码、配置与依赖说明、回归、完整演示 | 干净构建可复现收信、汇报与两种回复 |
